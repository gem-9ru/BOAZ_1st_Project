## 1. `크롤링/` — 데이터를 만든 곳

채용 사이트 **20곳**에서 직접 수집했다. 기준일 **2026-09-07**(그날 실제로 모집 중이던 공고).

```
수집  240,773행 → 정규화 227,214행 → 중복병합 161,351건 → 부산 25,135건
```

직업은 고용노동부 **한국고용직업분류(KECO) 6자리 코드**로 분류했고,
얼마나 확신하는지(`직종신뢰도`)와 못 붙인 이유(`직종미분류사유`)를 함께 남겼다.

## 2. `부산_청년유출_분석/` — 분석

수집 데이터에 공공통계를 붙여 원인을 좁혀 들어갔다.

```
build/   재현 스크립트 (원자료 → 결과 전부 재생성)
out/     분석 결과 CSV
docs/    차수별 분석 기록 (1차~12차) · 감사 · 검토 문서
```

## 이 저장소에 **없는** 데이터

재배포가 금지되어 있어 뺐다. 전부 `.gitignore`에 이유를 적어뒀다.

| 빠진 것 | 이유 | 어떻게 채우나 |
|---|---|---|
| **GOMS 원자료** (`부산_청년유출_분석/data/goms/`) | 한국고용정보원의 **개인 단위 마이크로데이터**.<br>이용 신청자 본인 연구 목적으로만 제공되고 **제3자 제공이 금지**된다 | 고용조사 분석시스템에서 직접 신청해 받은 뒤<br>`data/goms/pool/`에 `2016~2019.DTA`를 넣으면 재현된다 |
| 잡플래닛 수집분 | "무단 전재·수집·재배포 및 AI 학습 이용 금지" 고지 | 수집 코드는 남아 있다 |
| 잡부산시대 수집분 | 상세페이지에 재배포 금지 고지 | 수집 코드는 남아 있다 |

**분석 스크립트와 집계 결과는 전부 들어 있다.** 원자료만 없다.
즉 `out/*.csv`의 숫자와 대시보드는 그대로 검증할 수 있고,
원자료를 직접 받으면 처음부터 재현된다.

## 작업 규칙 3가지

1. **데이터를 합칠 때는 직업 이름이 아니라 6자리 직업코드로 붙인다.**
   문서마다 13개 큰 분류의 이름 체계가 다르다 —
   어떤 문서는 13번이 「정보통신관련직」, 고용24 공식 마스터는 13번이 「농림어업직」이다.

2. **개수를 비교하지 않는다.** 졸업생은 1년치, 공고는 하루 기준 모집 중이던 수다.
   기간이 다르므로 **비율(%)과 비율 차이(%p)로만** 말한다. 「몇 배」는 쓰지 않는다.

3. **새 숫자는 `EDA/숫자표_검증완료.md`에 먼저 올리고 쓴다.**
   특히 「대졸요구율」은 두 종류가 있다 — 전체 기준 9.2% / 학력 명시 기준 28.6%.
