# 부산 채용공고 데이터셋

BOAZ 1st Project · 국내 채용 사이트 20곳에서 **부산 지역 채용공고**를 수집해
하나의 스키마로 정규화하고, 사이트 간 중복을 병합한 데이터셋입니다.

**기준일 `2026-09-07`** — 이 날짜에 실제로 모집 중이던 공고만 담았습니다.

```
수집 240,773행 → 정규화 227,215행 → 중복병합 161,355건 → 부산 25,135건
```

## 결과물

### ⭐ 최종 데이터는 이 파일입니다

```
분석/부산_공고_분석용.csv       25,135건 · 24컬럼   ← 대시보드에 물릴 파일
부산/부산_공고_직종분류.csv     25,135건 · 64컬럼   ← 원본 (검증·추적용)
```

원본은 **원본 보존**이 원칙이라 가공값 옆에 사이트 원문을 함께 싣습니다. 검증에는
좋지만 집계에는 컬럼이 너무 많고 같은 뜻이 여러 표기로 흩어져 있습니다.
`분석/` 은 그것을 한 뜻 한 표기로 접은 결과입니다. → [분석/README.md](분석/README.md)

행 하나가 공고 하나입니다. 같은 공고가 여러 사이트에 올라온 경우 하나로 합쳐져 있습니다.

| 함께 나오는 파일 | 건수 | 설명 |
|---|---:|---|
| `분석/직종대분류_지표.csv` | 11 | 직종대분류 × 대졸요구·신입가능·정규직·연봉. **대시보드 기준 표** |
| `분석/시군구_직종대분류.csv` | 17 | 지역 × 직종 교차표 |
| `부산/부산_공고_통합.csv` | 25,135 | 직종코드 부여 전 · 46컬럼 |
| `부산/부산_직종별_집계.csv` | 459 | 세세분류별 건수 |
| `부산/부산_직종대분류_집계.csv` | 10 | 대분류별 건수 |
| `부산/부산_공고_원본.csv` | 57,369 | 병합 전 행 + 부산 판정근거·확실도 |
| `부산/부산_사이트별.csv` | 18 | 사이트별 건수 |

### 직종코드

`직무` 는 사이트마다 태그 체계가 달라 그대로는 집계가 안 된다. 공통 키로 KECO
직종코드를 붙였다. 공식 분류표(대13·중114·세1,215) 기준이고, 전 과정이
**결정적(deterministic)** 이라 몇 번 돌려도 같은 결과가 나온다.

```
세세분류(6자리)  7,307건 27.7%      대분류까지  22,060건 84.8%      미분류 3,075건 15.2%
```

정확도는 **실측했다.** `직종` 컬럼 2,559건이 공식 명칭과 완전일치해서 정답 세트가
된다. 5-fold 교차검증 결과 — 확실도 `강+중`(58.6%)은 대분류 98% · 세분류 95%,
`약`(37.6%)은 대분류 72%. 대분류 분포의 총변동거리는 **2.9%p** 로, 건별로는 12%가
틀리지만 비율은 거의 안 틀어진다.

### 컬럼 설계

**원본을 지우지 않습니다.** 가공값 옆에 사이트가 준 원문을 함께 싣습니다.

| 원문 | 채움 | 대응 가공값 |
|---|---:|---|
| `원본_직무` | 84% | `직무` (6개 출처 병합 토큰) |
| `원본_경력` | 99% | `경력구분` · `최소연차` |
| `원본_고용형태` | 48% | `고용형태표준` |
| `원본_지역` | 94% | `시도` · `시군구` |
| `원본_마감일` | 92% | `마감일` · `마감구분` |

**한 칸에 여러 정보를 담지 않습니다.**

```
근무시간  "주5일(월~금) 09:00 ~ 18:00"   → 근무요일 · 근무시작 · 근무종료
급여     "연봉 3,000만원 ~ 4,000만원"   → 급여형태 · 급여최소 · 급여최대
```

### 주요 필드 채움률

| 필드 | | 필드 | |
|---|---:|---|---:|
| 공고제목 | 100% | **급여** | **85%** |
| 경력구분 | 99% | 업종 · 채용인원 | 80% |
| 시도 · 직무 | 97% | **상세주소** | **51%** |
| 고용형태 | 95% | **자격요건** | **46%** |
| 시군구 | 95% | **직무상세** | **43%** |
| 마감일 | 92% | **담당업무** | **42%** |
| **학력** | **94%** | 급여최소 | 40% |
| 최소연차 · 회사명 | 89% | 근무시간 | 32% |
| 원본_직무 · 모집인원원문 | 83% | 우대사항 | 22% |
| | | **직종**(KECO) | **10%** |

**부산판정확실도** 로 걸러 쓸 수 있습니다 — 강 23,683 / 중 1,414 / 약 38.

> **담당업무 42%는 원본의 한계입니다.** 사이트마다 이 필드를 가진 정도가
> 크게 다릅니다(사람인 91%, 커리어 0%). 쓰기 전에
> [알려진 한계](docs/06_알려진_한계.md) 1장을 읽어주세요.
>
> **`직종` 은 한국고용직업분류(KECO) 명칭**입니다 — `재가 요양보호사`,
> `CNC 선반 조작원(NC 선반 조작원)`, `보육교사`. 고용24에서 받은 2,596건에 들어 있고,
> 자유 텍스트인 `직무` 와 달리 표준 체계라 직무별 집계·전공 매칭의 기준이 됩니다.

## 빠른 시작

```bash
pip install -r requirements.txt
```

`data/*.csv` 가 이미 있으므로 **재수집 없이** 파이프라인만 돌릴 수 있습니다.

```bash
python3 src/pipeline/normalize.py      # data/*.csv → build/공고_정규화.csv
python3 src/pipeline/dedup.py          # 중복 병합   → build/공고_통합.csv
python3 src/pipeline/extract_busan.py  # 부산 추출   → 부산/
```

| 하고 싶은 것 | 명령 |
|---|---|
| 중복 제거 로직 회귀 테스트 | `python3 src/pipeline/test_relation.py` |
| 수집 진행률 보기 | `bash 진행상황.sh` (`-w` 로 자동 갱신) |
| 특정 사이트 재수집 | `python3 src/wanted.py` (체크포인트, 중단해도 이어서) |
| 중단된 수집 결과 꺼내기 | `python3 src/flush_ckpt.py <이름>` |
