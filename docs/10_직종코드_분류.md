# 직종코드 분류

`직무` 칸은 사이트마다 태그 체계가 달라 그대로는 집계가 안 된다.

```
잡코리아  "국제금융, 금융, 은행, 문서관리, 전산입력, 서무, 행정"
사람인    "SNS마케팅, 광고마케팅, 바이럴마케팅"
커리어    "기구설계, 자동차부품개발, CATIA"
```

공고를 직무 기준으로 묶으려면 **공통 키**가 필요하다. 그게 KECO 직종코드다.

```
부산/부산_공고_직종분류.csv    25,135건 · 70컬럼   ← 최종 산출물
부산/부산_직종별_집계.csv      554종 (세세분류)
부산/부산_직종대분류_집계.csv   10종
부산/직종분류_정확도.csv       정답 2,559건 건별 채점 결과
data/keco/직종코드_마스터.csv  공식 분류표 1,342행
data/keco/직종코드_계층.csv    1,130코드 × 계층 — 팀 조인용
```

```bash
python3 src/pipeline/keco_run.py table   # 계층표
python3 src/pipeline/keco_run.py eval    # 5-fold 교차검증
python3 src/pipeline/keco_run.py build   # 산출물
```

# 1. 코드 체계 — 계층을 두 벌로 낸다

공식 분류표는 **대분류 13 · 중분류 114 · 세분류 1,215행**이다.
그런데 그대로 집계하면 안 되는 이유가 두 가지 있다.

## ① 트리가 아니라 DAG 다

세분류 **79개가 중분류 2곳 이상에 걸려** 있고, 그중 **67개는 대분류가 갈린다.**

```
026502 병원행정 사무원(원무)  →  017 경영지원 사무    (대분류 01 경영·사무)
                            →  044 그 외 보건·의료  (대분류 04 보건·의료)
024401 행사·이벤트 기획자     →  015 행정·경영 전문가  (대분류 01)
                            →  058 공연·음반 기획    (대분류 05 예술)
```

한 코드가 두 대분류에 속하니 대분류별 건수를 더하면 전체를 넘는다.
**상호배타(ME)가 깨진다.** 세분류 1,215행의 고유 코드는 실제로 **1,130개**다.

## ② 6자리 코드의 앞자리는 상위코드가 아니다

```
133200 응용 소프트웨어 개발자   superCd = 024   ← 133 이 아니다
```

1,215개 중 **1,212개가 앞3자리 ≠ superCd**. 앞자리를 잘라 상위분류를 만들면 전부 틀린다.
(v1 이 앞2자리를 대분류로 보고 `304000 간호사`를 농림어업으로 분류한 사고가 이것이다.)

## 그래서

| | 계층 | 성질 | 용도 |
|---|---|---|---|
| **① KECO 자릿수** | 1자리 대분류 **10** · 2자리 중분류 35 · 3자리 소분류 140 · 4자리 세분류 493 | 코드 1개 → 상위 1개. **정의상 MECE** | **집계 정본** |
| ② work24 표시 | 대분류 13 · 중분류 114 | 공식 명칭이 붙어 있음. DAG | 라벨 |

②는 `직종13대분류코드` · `직종114중분류코드` 로 함께 싣는다. 부모가 여럿이던
코드는 마스터 파일 최초 등장 부모를 정본으로 쓰고 `직종13대분류중복=Y` 로 표시했다.
**대분류 집계에는 ①을 쓰고, ②는 걸러 쓸 수 있게만 남겼다.**

## 팀 조인은 코드로 한다

13대분류 명칭은 문서마다 다르다. 서현 문서의 `13 정보통신관련직` 과
공식 마스터의 `13 농림어업직` 은 **다른 체계**다. 라벨로 조인하면 어긋난다.
학과↔직종 매핑도 **6자리 코드**를 키로 붙이고, 라벨은 `직종코드_계층.csv` 에서
파생시킨다.

# 2. 부여 경로 — 6개, 겹치지 않고 빠지지 않는다

`직종코드근거` 컬럼에 어느 경로로 붙었는지 남긴다.

| 경로 | 근거 | 확실도 | 부여 깊이 |
|---|---|---|---|
| **고용24직접** | `직종` 이 공식 명칭과 일치 | 강 | 세세분류 |
| **별칭일치** | 토큰이 공식 명칭·별칭과 일치 | 강 | 세세분류 |
| **학습사전** | 정답에서 학습한 토큰→코드 | 중 | 세세분류 |
| **상위합의** | 후보 분포를 표결 | 약 | **대분류만** |
| **미분류** | 근거 없음 | 미분류 | — |

경로가 상호배타이고, 미분류를 명시 카테고리로 둬서 합이 항상 25,135이 된다.

## 별칭은 손으로 적지 않았다

공식 명칭의 **괄호 안 동의어를 자동으로 펼친다.**

```
전기용접원(아크,알곤,티그용접원)
   → 티그용접원      접미어가 있으니 그대로 별칭
   → 아크 + 용접원   접미어가 없으니 본체의 머리말을 붙여 별칭
```

머리말(`용접원`·`조작원`·`관리자` …)도 손으로 적지 않는다. 본체명 1,130개의
뒤쪽 n-gram 중 5개 이상 명칭에 공통으로 나타나는 것만 자동 수집한다(153개).
결과: **명칭사전 1,325개 + 별칭사전 518개.** 유지보수할 손 사전이 없다.

## 이름 충돌은 일반형이 정답이다

```
550100 요양보호사              ← 일반형
550101 요양보호사(노인요양사)    ← 특수화. 괄호를 떼면 이름이 같아진다
027200 경리 사무원  /  027201~027207 경리 사무원(무역·운수·건설·제조 …)
```

모호한 게 아니라 **일반형이 정답**인 경우다. 같은 세분류(앞4자리) 안이면
`...00` 을 준다. 세분류가 갈리면 진짜 모호한 것이라 버린다.

## 학습사전은 정답에서 뽑는다 — 깊은 곳에서 실패하면 얕은 곳을 본다

정답 공고의 토큰↔코드 동시출현을 세고 **2건 이상 · 순도 75% 이상**만 채택한다.

처음에는 6자리에서 순도를 못 넘긴 토큰을 그냥 버렸다. 그런데 버려진 토큰 상당수가
**상위 레벨에서는 순도가 충분**하다.

```
"요양"   6자리로는 550100/550101/550102 로 갈리지만  앞4자리 5501 은 100%
"조리"   세세분류는 흩어지지만                        대분류 8 은 90%
```

그래서 6 → 4 → 3 → 2 → 1자리로 내려가며 처음 순도를 넘는 레벨에서 채택한다.

```
세세분류 확정 220개 + 상위접두 166개
```

상위접두 토큰은 세세분류로 쓰지 않는다. 그 접두에 속한 코드 전체를 표결 후보로
넣어 **표결이 그 방향으로 쏠리게** 한다. 정답에서 배운 방향이라 글자 겹침보다 낫다.
미분류가 3,075 → 1,345건으로 줄었다(이 단계까지의 값. 최종 1,206건).

```
조무사 → 307500 간호조무사        객실 → 561102 호텔·콘도 청소원
제빵사 → 871100 제과원 및 제빵사
```

## 본문 텍스트는 표결 후보로만 쓴다

`직무` 칸은 비었는데 담당업무·자격요건에 직업명이 그대로 적힌 공고가 있다.
공식 명칭 1,130개를 자유 텍스트에서 통째로 찾는다.

처음에는 이걸 6자리 확정(중급)으로 썼는데 홀드아웃에서 **세세분류 2% · 대분류 73%**
가 나왔다. `자격요건` 의 `간호사면허소지` 가 간호조무사 공고에 걸리는 식이다.
자유 텍스트에 직업명이 나온다는 것은 "그 직업이다" 가 아니라 "그 직업과 관련
있다" 는 뜻일 때가 많다. 그래서 확정으로 쓰지 않고 표결 후보로만 넘긴다.

## 표결은 대분류까지만 낸다

`영업`·`간호`·`생산` 같은 토큰은 세분류를 특정할 수 없다. 하지만 대분류는 특정된다.

```
가중치 = 1/(1+토큰위치) × (그 대분류에 속한 후보 비율)
```

- **토큰위치** — `직무` 칸은 앞쪽이 더 믿을 만한 출처에서 왔다
  (직종 > 직무키워드 > 모집분야 > 원본직무 > 제목 > 담당업무)
- **후보 비율** — 후보가 한 대분류에 쏠린 토큰일수록 강하게 센다.
  `간호`는 거의 전부 보건·의료라 강하고, `관리`는 흩어져서 약하다.
  손으로 만든 가중치 표가 필요 없다.

표결이 더 깊은 공통 앞자리를 내놓아도 **쓰지 않는다.** 홀드아웃 실측에서
중분류 55.7% · 소분류 35.1% · 세분류 23.6% 였다.
24% 정확도의 세분류를 데이터에 실으면 쓰는 사람을 속이는 셈이다.

## 전 과정이 결정적이다

LLM·임베딩을 쓰지 않는다. 같은 입력이면 몇 번 돌려도 같은 코드가 나온다.
사이트 간·실행 간 일관성이 이 데이터셋의 핵심 요구사항이기 때문이다.

# 5. 팀 13대분류 — 학과↔직종 미스매치의 기준축

직종 라벨 체계가 셋 돌아다닌다.

| | 개수 | 예 | 성질 |
|---|---:|---|---|
| ① KECO 6자리의 앞 1자리 | 10 | `8 설치·정비·생산` | 코드에서 바로 나옴. 정의상 MECE |
| ② work24 공용코드 depth-1 | 13 | `13 농림어업직` | DAG 라서 대분류가 갈린다 |
| **③ 팀 13대분류** | **13** | `13 정보통신관련직` | **서현님 학과 매핑의 기준** |

③이 미스매치 분석의 기준축이므로 이걸 정본 라벨로 싣는다.
**체계는 그대로 두고, 크롤링한 공고를 이 체계로 분류했다.**

①에서 ③으로 가는 규칙은 **KECO 2자리(중분류) 단위 매핑표**다. 2자리는 35개뿐이라
사람이 전부 훑어 검토할 수 있다.

```
data/keco/대분류13_매핑.csv    35행 — 팀이 고칠 수 있다
```

판단이 갈리는 행에는 근거를 적어 뒀다.

| KECO 중분류 | → | 왜 / 이견 |
|---|---|---|
| `84` 컴퓨터·휴대폰·방송장비 수리 | 13 정보통신관련직 | 설치·정비지만 「정보통신관련」 |
| `87` 제과·제빵·정육 등 식품가공 | 10 설치·정비·생산직 | 13분류에 식품 슬롯이 없다 |
| `82` 금속가공 기계 조작 | 10 설치·정비·생산직 | 「재료」로 보면 12도 가능 |
| `89` 제조 단순 종사원 | 10 설치·정비·생산직 | 기계·화학 양쪽에 걸친다 |

## KECO 10대분류 ↔ 팀 13분류 교차표 (세세분류 1,130개)

**7개는 그대로 옮겨지고, 3개가 쪼개진다.** 거꾸로 합쳐지는 건 하나뿐이다.

| KECO 10대분류 | 세세분류 | → 팀 13분류 | 개수 | KECO 중분류 |
|---|---:|---|---:|---|

| `2` 교육·법률·복지·공안·군인 | 90 | `03` 교육·법률·사회복지·경찰·소방직 및 군인 | 90 | 21~25 |
| `3` 보건·의료 | 39 | `04` 보건·의료직 | 39 | 30 |
| `4` 예술·디자인·방송·스포츠 | 89 | `05` 예술·디자인·방송·스포츠직 | 89 | 41,42 |
| `5` 미용·여행·숙박·음식·경비·돌봄·청소 | 107 | `06` 미용·여행·숙박·음식·경비·청소직 | 107 | 51~56 |

| | | **`08` 운전·운송직** | **44** | **62** |

| `8` 설치·정비·생산 | 271 | **`10` 설치·정비·생산직** | **207** | 81,82,83,87,88,89 |
| | | **`12` 재료·화학·섬유·가스·에너지·환경** | **56** | **85,86** |
| | | **`13` 정보통신관련직** | **8** | **84** |
| `9` 농림어업 | 19 | `11` 농림어업직 | 19 | 90 |

**쪼개지는 셋**

```
KECO 1 연구·공학기술        → 02 연구·공학기술 + 13 정보통신          (ICT 를 따로 뺀다)
KECO 6 영업·판매·운전·운송   → 07 영업·판매 + 08 운전·운송            (판매와 운송을 나눈다)
KECO 8 설치·정비·생산        → 10 설치·정비·생산 + 12 재료·화학 + 13 정보통신
```

**합쳐지는 하나**

```
13 정보통신관련직 ← KECO 1(38개, 중분류 13 개발·연구) + KECO 8(8개, 중분류 84 설치·수리)
```

13분류만 KECO 대분류 둘에서 모인다. 나머지 12개는 KECO 대분류 하나에서만 온다.
그래서 **13분류도 코드 1개 → 분류 1개** 이고 집계가 겹치지 않는다.

## KECO 1자리만으로는 13분류가 안 나온다

```
KECO 1 → 02 연구·공학기술 / 13 정보통신
KECO 6 → 07 영업·판매    / 08 운전·운송
KECO 8 → 10 설치·정비·생산 / 12 재료·화학 / 13 정보통신
```

`약` 등급은 KECO 1자리만 나오므로, 이 셋은 파생이 실패한다. 그래서 **13대분류도
같은 표결로** 정한다 — 후보 코드들의 13분류를 가중 표결한다. 가중치 규칙은 대분류
표결과 같다.

## 실측

| 등급 | 건수 | 13대분류 정확도 |
|---|---:|---:|
| 강 | 1,093 | **98.3%** |
| 중 | 407 | **97.3%** |
| 약 | 984 | 75.1% |
| **전체** | 2,500 (97.7%) | **88.8%** |

KECO 10대분류(88.2%)와 같은 수준이다. **미스매치 비교에 그대로 쓸 수 있다.**
부산 25,135건 중 **24,383건(97.0%)** 에 13대분류가 붙는다.

`분석/직종13분류_지표.csv` 가 13분류 × 대졸요구·신입가능·정규직·연봉 기준표다.

# 6. `약` 등급 추정 — 직무 사전으로, 근거를 남긴다

처음엔 "표결에서 가중치가 가장 큰 후보"를 추정값으로 썼다. 숫자는 나오지만
**왜 그 코드인지 설명할 수 없고** 홀드아웃 세세분류 정확도가 7.0% 였다.

직무 사전으로 바꿨다. 사전에 걸리면 그 항목이 근거가 된다.

```
data/keco/직무사전.csv    646행 (학습 466 · 수동 180)
```

| 열 | 무엇 |
|---|---|
`토큰` | 직무 토큰 (정규화)
`직종코드` `직종명` | 6자리 세세분류. 모르면 비운다
`직종분류코드` `직종분류명` | 팀 13대분류. 6자리를 못 정해도 직군은 아는 경우
`출처` | `학습`(정답에서 자동) / `수동`(사람이 등재)
`순도` `건수` | 학습분의 근거 수치
`근거` | 한 줄 설명

## 두 갈래로 만든다

**① 학습분 468행** — 고용24 정답 2,559건의 토큰↔코드 동시출현을 센다.
6자리는 **3건 이상 · 순도 60% 이상**, 13대분류는 2건·50% 이상.

```
조무사   -> 307500 간호조무사    정답 34건 중 32건
생산     -> (6자리 없음) 10 설치·정비·생산직   정답 268건 중 189건 — 세세분류는 흩어진다
```

6자리 기준을 13분류보다 엄격하게 뒀다. 처음엔 둘 다 2건·50% 로 받았더니
`조경 → 140400`(정답 4건 중 2건)이 토목·기계 건설사업관리 공고에 붙었다.
표본이 작을 때 50% 는 동전 던지기다.

**② 수동 등재분 57행** — KECO 어휘와 채용시장 어휘의 간극을 사람이 메운다.

```
생산직    (6자리 없음) 10   KECO 는 `~원` 을 쓴다. 공정은 특정 불가
병동      304000 간호사   병동은 근무부서. 부산 공고는 간호사 모집이 대다수
원무과    026502 병원행정 사무원(원무)   진료가 아니라 사무다
md        024302 머천다이저(MD)   공식 명칭 괄호 안에 있어 별칭 필터에서 빠졌다
실장      (비움)   직급이라 직업을 특정할 수 없다 — 추정하지 않는다
```

**검토 가능하게 만든 게 실제로 값을 했다.** 손으로 적은 57행을 분류표와 대조하니
2건이 틀렸다 — `564100` 을 경비원으로 알고 `당직전담사`·`보안` 에 붙였는데
그건 **계기 검침원 및 가스 점검원**이었다(경비원은 `541300`). `간병` 도
`550400 장애인 돌봄 종사원` 으로 잘못 넣었다(간병인은 `550201`).

## 실측 — 이전 방식의 6배

| | 대분류 | 중분류 | 소분류 | 세분류 | 세세분류 |
|---|---:|---:|---:|---:|---:|
| 표결 가중 최빈 (이전) | — | 42.0% | 26.2% | 19.9% | **7.0%** |
| **직무 사전 (현재)** | **85.6%** | **75.6%** | 56.8% | 54.0% | **40.8%** |

여전히 `직종코드` 에는 넣지 않는다 — `강`·`중`(세분류 95%)과 섞이면 구분이 안 된다.
`직종추정코드`·`직종추정명`·`직종추정근거` 로 싣는다. **근거 열이 있으니 왜 그
코드인지 한 줄로 확인할 수 있다.**

```
직종추정근거  사전(수동) 「원무과」 — 병원행정 사무원(원무). 진료가 아니라 사무다
              사전(학습) 「조무사」 — 정답 34건 중 32건이 307500 간호조무사
              후보 표결 — 지지 후보들의 13대분류가 10 으로 모였다
```

# 8. 추천 1순위 자동 부여 — 규칙과 출처를 둘 다 본다

미분류 공고에 추천 1순위를 자동으로 붙여 달라는 요청을 받았다. 그대로 다 붙이면
안 되므로 **어느 규칙이 걸렸는지 × 어느 출처에서 걸렸는지** 로 나눠 실측했다.
정답 2,559건 기준.

| 규칙 | 출처 | 건수 | 세세분류 | 세분류 | 대분류 | | |
|---|---|---:|---:|---:|---:|---|---|
| `name` 공식 명칭 일치 | 직무태그 | 772 | 52.2% | **84.7%** | **95.3%** | ✅ | 쓴다 |
| `lex` 직무사전 일치 | 직무태그 | 625 | 48.2% | 64.2% | **89.1%** | ✅ | 쓴다 |
| `head` 머리말 | 직무태그 | 78 | 12.8% | 19.2% | 70.5% | ❌ | |
| `name` | 제목·본문 | 73 | 11.0% | 25.4% | 65.8% | ❌ | |
| `ngram` 글자겹침 | — | 620 | 15.2% | 25.2% | 57.7% | ❌ | |
| `lex` | 제목·본문 | 132 | 15.4% | 34.8% | 56.8% | ❌ | |
| `head` | 제목·본문 | 30 | 3.3% | 3.3% | 50.0% | ❌ | |
| `qual` 한정어 | 직무태그 | 115 | 9.6% | 9.6% | 40.0% | ❌ | |
| `qual` | 제목·본문 | 69 | 2.9% | 2.9% | 25.4% | ❌ | |

**버린 규칙이 무엇을 만들었나** — 이게 안 쓰는 이유다.

```
qual   "일과 육아를 동시에 … 재능선생님 모집"   → «아파트» 가 걸려 경리 사무원(아파트·빌딩)
head   "2026학년도 온천초등학교 통학차량안전도우미"  → «도우미» 만 걸려 응원단원
head   "iOS Developer"                    → «개발자» 만 걸려 금융 및 보험 상품 개발자
ngram  "클라우드 엔지니어 (부산)"              → 모니터 요원
```

`name`+직무태그와 `lex`+직무태그만 써서 **804건**을 붙였다.

```
2026년 청룡초등학교 당직전담사 채용 공고     → 541300 시설 및 특수 경비원
사월별채마사지 바디테라피스트 야간프리랜서      → 511400 피부 및 체형 관리사
통신 주력/ CS / 전산 관리 모집             → 029202 콜센터 상담원(콜센터·고객센터·CS센터)
```

근거는 `직종추정근거` 에 남는다.

```
추천 1순위 — 직무 태그에 「당직전담사」 가 있어 541300 시설 및 특수 경비원 로 봤다
(직무사전 일치 · 이 경로 실측 대분류 89.1% · 세분류 64.2%)
```

등급은 `약` 이다. 세세분류가 48~52% 라 `강`·`중`(95%)과 섞으면 안 된다.
`직종코드근거 = 추천1순위` 로 걸러 낼 수 있다.

**결과** 미분류 2,666 → **1,345건(5.4%)** · 세세분류 7,308 → **8,581건** ·
13대분류 채움 **96.6%**

> 이 절의 숫자는 **이 단계까지 적용한 시점**의 값이다.
> 최종값(미분류 1,206건 · 4.8% · 13대분류 97.0%)은 13장에 있다.

## 사전을 3차까지 늘렸다 — 자동화의 실제 동력

추천 1순위 자동 부여는 사전에 걸리는 만큼만 늘어난다. 그래서 **미분류로 남은
공고의 직무 토큰을 빈도순으로 뽑아 사전에 등재하는 것을 3번 반복**했다.

| 차수 | 등재 | 남은 미분류 | 13대분류 채움 |
|---|---|---:|---:|
| 시작 | 수동 57행 | 2,666 (10.6%) | 91.9% |
| 1차 | +58행 — `데이터엔지니어`·`공인중개사`·`보험설계사`·`네일리스트` … | 1,985 (7.9%) | 93.1% |
| 2차 | +43행 — `전략기획`·`프런트`·`검안사`·`파티쉐`·`당직` … | 1,890 (7.5%) | 93.6% |
| 3차 | +22행 — `홀직원`·`아웃바운드`·`시설과장`·`광고디자인` … | **1,345 (5.4%)** | **96.6%** |

3차에서 멈춘 이유가 데이터에 있다. 남은 `분류표없음` 487건의 토큰 665개 중
**590개가 딱 한 번만 나온다.** 여기서부터는 사전 한 줄이 공고 한 건을 고치는
1:1 작업이라, 사전을 늘리는 것과 공고를 직접 붙이는 것이 같은 일이 된다.

## 사전을 늘리다 발견한 것 — 긴 토큰이 이겨야 한다

`엔지니어` 는 사전에 "추정하지 않는다" 로 등재돼 있다(분야 없이는 특정 불가).
그런데 `데이터엔지니어`·`백엔드엔지니어` 를 등재해도 반영이 안 됐다.
토큰을 앞에서부터 훑다가 짧은 `엔지니어` 가 먼저 걸려 그 자리에서 멈추기 때문이다.
**긴 토큰부터 보도록** 고쳤다.

## 규칙을 고용24 정답으로 검증했다

규칙은 미분류 공고에만 적용된다. 정답 세트 2,559건은 손대지 않으므로
**완전한 홀드아웃**이다. 여기서 규칙이 발화하는 공고를 재 봤다.

| | 발화 | 13대분류 일치 |
|---|---:|---:|
| 처음 판 | 78건 | 66.7% |
| 좁힌 뒤 | 34건 | **94.1%** |

처음 판은 패턴이 느슨해 딴 직무를 물었다. 정답이 알려준 것:

| 정답 | 처음 규칙 | 무엇이 틀렸나 |
|---|---|---|
| `026202` 영업 기획·관리 사무원 | `81` 기계 정비 | «원광밸브(주) 영업관리» — **회사명**에 장비명이 들었다 |
| `231400` 직업 관련 상담사 | `029212` 취업 알선원 | 국민취업지원제도 공고 3건이 모두 231400 이다 |
| `016900` 기타 건설·생산 관리자 | `140203` 건축시공 기술자 | «현장관리자» 는 기술자가 아니라 **관리자**로 붙는다 |
| `531800` 단체급식 조리사 | `029210` 병원 코디네이터 | 병원의 «조리실장» — `실장` 이 조리 직무일 수 있다 |

고쳐서 반영한 것은 **정답이 3건 이상 같은 방향을 가리킨 것**(국민취업지원제도,
현장관리자)과 **패턴 자체가 오작동한 것**(장비명·조리실장)이다.
`(?!...)` 부정 룩어헤드를 정규식에 넣었더니 교대(`|`) 우선순위 때문에 첫 분기만
걸렸다 — 그래서 제외 조건을 `EXCLUDE` 로 따로 뺐다.

남은 불일치 2건은 실제로 애매한 것이다. 국민취업지원제도는 정답 자체가
231400 3건 · 029212 1건으로 갈리고, «㈜씨넷» 은 전기·전자 업종으로 잡히지만
실은 네트워크 회사다.

# 11. 하지 않은 것

| 방법 | 안 쓴 이유 |
|---|---|
| **LLM 분류** | 비결정적. 같은 공고가 실행마다 다른 코드를 받으면 사이트 간 일관성이 깨진다 |
| **임베딩 유사도** | 결정적이긴 하나 임계값 밖 오분류를 설명할 수 없다. 룰은 `직종매칭토큰` 으로 근거가 남는다 |
| **`업종` 을 보조 신호로** | 정답 세트(고용24)의 업종 어휘가 나머지 공고의 **21.8%만 커버**한다. 나머지 78%에 대해선 정확도를 측정할 방법이 없다. 측정 못 하는 규칙은 넣지 않았다 |
| **미분류를 억지로 채우기** | `MD`·`테라피스트`·`수의테크니션` 은 공식 분류표에 없다. 4.8% 를 한계 지표로 밝히는 쪽이 정직하다 |

# 12. 알려진 오분류

**회사명이 직무 토큰으로 새는 경우** — 상위 파이프라인(`직무` 칸 생성)의 한계다.

```
"천지개발(주) 안전보건팀 경력 모집"  →  토큰 "개발"  →  연구·공학기술 (오분류)
```

`직종매칭토큰` 컬럼으로 이런 건을 찾아낼 수 있다.
