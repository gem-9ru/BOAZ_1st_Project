# 대상 사이트별 수집 방식

18개 사이트. 각각 데이터를 꺼내는 경로와 주의점이 다릅니다.

---

## 종합 채용

### 잡코리아 — `src/jobkorea.py` · 107,812건
sitemap(agi) 으로 전체 공고 URL 을 확보한 뒤 상세페이지의 JSON-LD `JobPosting` 을 파싱합니다.
sitemap 기반이라 전수가 보장됩니다.

- `occupationalCategory` → 직무, `validThrough` → 마감일, `experienceRequirements` → 경력
- JSON-LD 에 직무가 없으면 본문의 "모집분야" 항목에서 추출

### 잡코리아 추가분 — `src/jobkorea_extra.py` · 28,241건
sitemap 에 노출되지 않는 잡코리아 공고입니다.
다른 사이트가 걸어둔 잡코리아 인링크를 모아 역으로 확보했습니다.

### 잡코리아 직무 보강 — `src/jobkorea_duty.py`
직무 칸을 상세페이지의 "모집분야" 로 교체하는 보강 패스입니다. 부산 지역만 대상으로 돌립니다.

### 리멤버커리어 — `src/remember.py` · 13,499건
`sitemap-jobs.xml` + 상세 JSON-LD.

### 커리어 — `src/career.py` · 11,862건
목록에 **서버측 100건 캡**이 있습니다.
`job.career.co.kr` 서브도메인에서 지역 × 직무(`i_jc1=A0..N0` 문자 코드)로 조건을 쪼개
각 슬라이스를 캡 아래로 내린 뒤 합칩니다.

### 잡플래닛 — `src/jobplanet.py` · 1,070건
내부 REST API. 딥페이지네이션 1만건 캡을 조건 분할로 우회합니다.
**단 이 사이트는 무단 수집 금지를 명시**하고 있어 잡코리아 데이터로 대체했습니다.
→ [03_정책감사.md](03_정책감사.md), [06_알려진_한계.md](06_알려진_한계.md)

## 지역

### 부산일자리정보망 — `src/busanjob.py` · 25,895건
부산광역시가 운영하는 공공 포털. 서버 렌더링이라 정적 HTML 에 목록이 들어 있습니다.

```
/view.do?no={메뉴}&pgMode=index&pageIndex={N}
  no=1308 기업채용 / 1309 공공채용 / 1310 해외채용
```

- 항목 셀렉터 `ul.emif-lst > li`, 페이지당 12건
- **메뉴마다 링크 방식이 다릅니다.** 기업·공공채용은 `onclick="show('817303')"` 내부 링크,
  해외채용만 월드잡플러스 외부 href 를 직접 겁니다. 해외채용은 필드 배치도 달라
  `.item` 첫 칸이 직무, `.batcont.country` 가 국가입니다
- **자체 공고가 아닙니다.** 사람인·잡코리아·고용24·알리오 공고를 함께 노출하며
  `provide-bat` 클래스가 출처를 알려줍니다. 이 값을 `외부원본ID` 로 보존해
  중복 판정 근거로 씁니다

출처 분포: 사람인 15,519 / 잡코리아 5,751 / 워크넷 3,965 / 해외 569 / 알리오 53 / 수동 20 / 부산자체 18

> 현재 **목록만** 수집하고 상세페이지는 받지 않았습니다. 이 때문에 직무·고용형태에
> 결손이 있습니다. → [06_알려진_한계.md](06_알려진_한계.md)

## IT

### 원티드 — `src/wanted.py` · 11,390건
공개 REST API `v4/jobs`. 총건수를 안 주므로 offset 이분 탐색으로 끝을 찾습니다.

카테고리가 불투명한 `category_tags` 숫자로만 오는데,
`/wdlist/{parent}/{child}` 페이지 제목이 카테고리명을 담고 있어
이를 긁어 193개 매핑표 `src/wanted_categories.json` 를 만들었습니다.

### 점핏 — `src/jumpit.py` · 760건
`jumpit-api.saramin.co.kr/api/positions` 공개 JSON API. 인증 불필요.
