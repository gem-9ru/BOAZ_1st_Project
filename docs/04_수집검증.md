# 수집 검증

"다 받았다"를 **사이트가 밝힌 숫자와 대조해서** 확인하는 절차입니다.
대조 없이 수집을 끝내면 결손을 발견할 방법이 없습니다.

---

## 수집 전

### 1단계 · 정책 확인
- [ ] `robots.txt` 조회 및 `can_fetch()` 판정
- [ ] **렌더링된 페이지**의 푸터·본문 크롤링 금지 고지
- [ ] 이용약관 회원 의무 조항 (계정 사용 시)

→ [03_정책감사.md](03_정책감사.md)

### 2단계 · 정본 총건수 확보
사이트가 스스로 밝힌 숫자를 먼저 찾습니다. 없으면 **없다고 기록**합니다.

- [ ] "전체 N건" 표기
- [ ] API 응답의 `total_count` / `totalCount` / `intTotalRecordCount`
- [ ] sitemap 의 URL 개수
- [ ] 목록 마지막 페이지 번호 이분 탐색 × 페이지당 건수

### 3단계 · 구조 전수 확인
- [ ] 메뉴·탭·카테고리를 **빠짐없이 열거**했는가
- [ ] **메뉴마다 항목 링크 방식이 같은가**
- [ ] **메뉴마다 필드 배치가 같은가**
- [ ] 페이지네이션 파라미터를 실측했는가 (추측 금지)
- [ ] 서버측 결과 캡이 있는가

> 링크 방식과 필드 배치는 메뉴별로 다를 수 있습니다.
> 부산일자리정보망은 기업·공공채용이 `onclick="show(id)"` 내부 링크인데
> 해외채용만 외부 href 를 직접 걸고, `.item` 첫 칸이 직무입니다.

---

## 수집 후

### 4단계 · 정본 대조 (필수)
- [ ] 수집 건수 / 정본 총건수 ≥ **98%**. 미만이면 원인 규명
- [ ] **건수가 코드 상한의 배수와 정확히 일치하지 않을 것**
      (`MAX_PAGE=80` × 10건 = 정확히 800건이면 잘린 것)
- [ ] **증가분 0으로 끝난 메뉴가 없을 것** — 파싱 실패 신호
- [ ] **고유 ID 수 == 행 수** — 쿼리스트링만 다른 같은 공고 방지
- [ ] 필드별 채움률 — **0% 와 100% 는 둘 다 의심**

> 100% 를 의심하는 이유: 잘못된 값이 일괄로 들어가도 100% 가 됩니다.
> 부산일자리정보망 직무 칸은 100% 채워져 있지만 값이 전부 메뉴 이름입니다.
> → [06_알려진_한계.md](06_알려진_한계.md) 1장

### 5단계 · 필드 검증
- [ ] 직무 칸에 **안내문·업종·고용형태·메뉴명**이 들어가지 않았는가
- [ ] 채움률이 낮은 필드는 **목록 → 상세 → 본문 텍스트 → 상세 API** 네 층을 다 확인했는가
- [ ] 표본 행을 직접 눈으로 읽었는가

> "원본에 없다"는 판정은 네 층을 다 본 뒤에만 내립니다.
> 목록에 없어도 상세에 있고, 상세 HTML 에 없어도 스크립트 변수에 있는 경우가 있습니다.

## 자주 놓치는 것 셋

아래 세 가지는 전부 실제로 크게 데인 적이 있습니다.

---

### 지역이 목적이면 지역 필터를 직접 쓴다

전국을 받아 지역으로 거르면 **다지역 공고가 통째로 빠진다.**
상세페이지 구조화 데이터가 주소를 하나만 주기 때문입니다.

```
실제 공고   "서울, 경기, 대구, 경북, 부산, 경남"
JSON-LD    jobLocation 1개 → "서울 중구"
결과       부산 집계에서 탈락
```

잡코리아 4,149 → 8,671, 커리어 852 → 5,209 로 두 배 이상 벌어졌습니다.
→ 상세: [08_부산_전수조사.md](08_부산_전수조사.md)

- [ ] 사이트에 지역 필터가 있는가. 파라미터가 무엇인가
- [ ] 파라미터를 보냈을 때 **실제로 필터가 적용되는가** (건수가 줄어드는가)
      점핏·나라일터·건설워커는 파라미터를 받아도 전국 결과를 돌려줍니다
- [ ] 지역 필터 결과가 사이트 표기 건수와 맞는가

---

### 목록 페이지네이션이 진짜로 되는가

- [ ] 페이지 2와 페이지 3의 **결과 집합이 서로 다른가**
      같으면 파라미터가 무시되는 것입니다. 잡코리아는 `Page`/`Page_No` 를 보내도
      항상 1페이지를 돌려줬고, 실제 페이저는 `POST /Recruit/Home/_GI_List/` 였습니다
- [ ] 목록 첫 페이지만 읽고 끝내지 않았는가
      널스케이프가 그랬습니다. 314건을 받았는데 부산이 0건이었고,
      지역 필터로 보니 부산만 49건이었습니다
- [ ] 코드에 걸어둔 `MAX_PAGE` 가 실제 한계인가, 내가 정한 숫자인가
      커리어는 `MAX_PAGE=12`(600건) 상한 때문에 84%가 잘렸습니다.
      실측해보니 페이지 100까지 정상 동작했습니다

---

### 로그가 아니라 결과 파일을 본다

`Site.save()` 는 고정 12칸만 CSV 로 씁니다. 그 밖의 값을 `s.add()` 로 넘기면
메모리에는 남지만 **파일에는 안 담깁니다.**

실행 로그에는 "학력 8,639건 확보" 로 찍혔는데 CSV 에는 학력 컬럼 자체가 없었습니다.
대졸 수요 분석에 필요한 필드라 놓쳤으면 치명적이었습니다.

- [ ] 수집 직후 **CSV 헤더**를 확인했는가
- [ ] 채움률을 로그가 아니라 **저장된 파일**에서 셌는가
- [ ] 기본 12칸 밖의 값을 받는다면 `site.extra_cols` 를 지정했는가

## 자동 검증 도구

```bash
python3 src/audit/coverage_check.py    # 정본 총건수 vs 수집 건수
python3 src/audit/policy_audit.py      # robots · 게시 고지 · 약관
```

`coverage_check.py` 는 전국 수집 사이트의 정본 조회 함수 17개를 갖고 있습니다.
부산 지역 필터로 받은 사이트의 정본 대조는 [08_부산_전수조사.md](08_부산_전수조사.md) 에 있습니다.
신규 사이트를 추가하면 **그 사이트의 정본 조회기도 함께 추가**합니다.
정본을 못 구하면 결과에 그렇게 남깁니다.
