# 수집 파이프라인

원본 사이트에서 최종 부산 CSV까지, 데이터가 거치는 전 과정입니다.

```
 ①  정책 감사        수집해도 되는 사이트인지 판정
     ↓
 ②  정본 총건수 확보   사이트가 스스로 밝힌 "전체 N건"을 먼저 확보
     ↓
 ③  사이트별 수집      src/{사이트}.py       →  data/{사이트}.csv     213,169행
     ↓
 ④  수집 검증         audit/coverage_check.py  정본 대비 98% 이상인지
     ↓
 ⑤  정규화            pipeline/normalize.py  →  build/공고_정규화.csv  200,502행
     ↓
 ⑥  중복 병합         pipeline/dedup.py      →  build/공고_통합.csv    157,007건
     ↓
 ⑦  부산 추출         pipeline/extract_busan.py → 부산/               20,622건
```

---

## ① 정책 감사

수집 **전에** 세 층을 확인합니다. 셋 중 하나라도 금지면 수집하지 않습니다.

| 층 | 확인 대상 | 구속 범위 |
|---|---|---|
| 1 | `robots.txt` | 크롤러 일반 |
| 2 | 페이지 본문·푸터 고지 | 비회원 포함 |
| 3 | 이용약관 회원 의무 | 계정 보유자 |

2층은 **반드시 렌더링된 페이지**에서 확인합니다. 푸터가 클라이언트 렌더링이면
`requests` + BeautifulSoup 으로는 보이지 않습니다.

3층 때문에 **계정을 만들면 오히려 제약이 늘어납니다.** "서비스로 얻은 정보의 복제 금지"
같은 조항이 계약상 구속력을 갖기 때문입니다.

→ 상세: [03_정책감사.md](03_정책감사.md)

## ② 정본 총건수 확보

수집을 시작하기 전에 **사이트가 밝힌 전체 건수**를 먼저 찾아 기록합니다.
이 숫자가 없으면 "다 받았다"를 검증할 방법이 없습니다.

찾는 곳은 네 가지입니다.

- 목록 화면의 "전체 N건" 표기
- API 응답의 `total_count` / `totalCount` / `intTotalRecordCount`
- sitemap 의 URL 개수
- 마지막 페이지 번호 이분 탐색 × 페이지당 건수

## ③ 사이트별 수집

사이트마다 데이터를 꺼내는 경로가 다릅니다. 우선순위는 아래 순입니다.

| 경로 | 사이트 | 장점 |
|---|---|---|
| 공개 REST API | 원티드, 점핏, 캐치, 자소설닷컴, 잡플래닛 | 필드가 구조화돼 있음 |
| sitemap + 상세 JSON-LD | 잡코리아, 리멤버커리어 | 전수 보장 |
| Next.js `__NEXT_DATA__` | 링커리어 | SSR 상태를 그대로 파싱 |
| 목록 HTML 파싱 | 부산일자리정보망, 커리어, 나라일터, 잡알리오 | 그 외 |
| 목록 → 상세 meta/JSON-LD | 게임잡, 건설워커, 미디어잡 | 목록에 없는 필드 보강 |

**공통 처리 — `src/common.py`**

- `RateLimiter` : 전역 요청 간격 제어. 사이트별 `delay` 지정
- 체크포인트 : 수집분을 `logs/{사이트}.ckpt.jsonl` 에 append.
  중단해도 재실행하면 이어서 진행합니다
- `parse_jobposting_ld()` : JSON-LD `JobPosting` 스키마 파서.
  `occupationalCategory`(직무), `validThrough`(마감), `experienceRequirements`(경력) 추출
- 세션 재사용, 재시도, 실패 URL 기록

**목록 캡 우회**

서버가 결과를 잘라내는 사이트가 있습니다(예: 목록 100건, 딥페이지네이션 1만건 상한).
이럴 때는 **지역 × 직무로 조건을 쪼개** 각 슬라이스가 캡 아래로 내려오게 만든 뒤 합칩니다.
커리어는 이 방식으로 100건 → 11,862건이 됐습니다.

## ④ 수집 검증

`src/audit/coverage_check.py` 가 사이트별 정본 총건수를 다시 조회해 수집분과 대조합니다.
17개 사이트에 대한 개별 조회 함수가 들어 있습니다.

통과 기준과 위험 신호:

- [ ] 수집 건수 / 정본 건수 ≥ **98%**
- [ ] 건수가 코드에 박아둔 상한과 **정확히 일치하지 않을 것** (예: 800 = 80페이지 × 10)
- [ ] 신규 0건으로 끝난 메뉴가 없을 것
- [ ] 고유 ID 개수 == 행 수 (쿼리스트링만 다른 같은 공고 방지)

→ 상세: [04_수집검증.md](04_수집검증.md)

## ⑤ 정규화 — `pipeline/normalize.py`

사이트마다 다른 스키마를 하나로 합치고, 네 가지 일을 합니다.

### 5-1. 스키마 통일

18개 사이트의 컬럼을 공통 스키마로 매핑합니다.
지역 문자열은 `시도` / `시군구` / `지역원문` 으로 분해하고,
`시군구 → 시도` 역매핑 표를 둬서 "해운대구"만 있어도 시도를 부산으로 채웁니다.

### 5-2. 알바 공고 제외 — 3,084행

알바는 대상이 아닙니다. 단순 키워드 매칭이 아니라 **어디에서 매칭됐는지**로 판정합니다.

| 매칭 위치 | 판정 |
|---|---|
| 공고제목 | 제외 |
| 고용형태 칸만 | 정규/계약/인턴이 함께 있으면 유지 |
| 직무 설명문만 | 유지 |

"아르바이트생 관리" 같은 정규직 공고가 제목이 아닌 본문에서 걸리는 것을 막기 위한 구분입니다.

### 5-3. 마감 공고 제외 — 9,157행

`SNAPSHOT = "2026-09-07"` 보다 마감일이 앞서면 버립니다.
"상시채용" / "채용시 마감" 처럼 날짜가 없는 것은 유지합니다.

### 5-4. 직무 보강

직무 칸이 비었거나 "기업채용" 같은 분류명뿐인 공고가 많습니다.
공고제목에서 직무를 추출해 채웁니다.

| 방법 | 예 |
|---|---|
| 직무 어휘 사전 (약 350개) | "간호조무사", "백엔드", "요양보호사" |
| 직함 어미 패턴 | ...반장 / 팀장 / 기사 / 관리사 / 조리사 / 치료사 |
| 존칭 패턴 | "피부관리사**님**" |
| 부서·병동 패턴 | 원무과 / 외래 / 병동 / 수술실 |

추출한 토큰은 회사명과 겹치거나, 숫자·비직무 라벨이면 버립니다.
괄호가 짝이 안 맞으면 복구합니다.

> **한국어 정규식 주의**
> `(?<![가-힣])` 같은 단어경계 룩비하인드를 쓰면 안 됩니다.
> 한국어는 조사·수식어가 공백 없이 이어져서("피부과에서 피부관리사님을")
> 앞 글자가 거의 항상 한글이라 매칭이 사실상 사라집니다.

## ⑥ 중복 병합 — `pipeline/dedup.py`

같은 공고가 여러 사이트에 올라옵니다. Union-Find 로 묶어 하나의 `통합키`를 부여합니다.
3단계를 순서대로 적용하며, 뒤 단계일수록 보수적입니다.

| 단계 | 근거 | 병합 |
|---|---|---:|
| 1 | 외부원본ID 일치 (사이트가 밝힌 원본 출처) | 0쌍 |
| 2 | 회사키 + 제목키 완전일치 | 37,092쌍 |
| 3 | 회사키 동일 + 제목 유사도 | 6,403쌍 |

**회사키** — 법인격 표기를 제거해 정규화합니다. `(주)`, `㈜`, `주식회사`, `유한회사` 등.
공백 변형(`CJ 생수` vs `CJ생수`)도 함께 흡수합니다.

**3단계 근무형태 가드** — 회사·직무가 같아도 아래 어휘가 서로 다르면 병합하지 않습니다.

```
야간 주간 심야 오전 오후 저녁 새벽 주말 평일 교대 2교대 3교대 격일
상근 전담 야간전담 당직 재택 파견 출장 상주 순회 단기 장기 주5일 주6일 ...
```

같은 병원의 "야간전담 간호사"와 "주간 간호사"는 **다른 공고**이기 때문입니다.

**회귀 테스트** — `pipeline/test_relation.py` 18케이스. 로직 수정 시 반드시 통과해야 합니다.

결과: 200,502행 → **157,007건** (43,495행 병합, 21.7%).
2개 이상 사이트에 동시 게재된 공고는 10,740건입니다.

## ⑦ 부산 추출 — `pipeline/extract_busan.py`

네 가지 근거 중 하나라도 맞으면 부산으로 판정합니다.

| 판정근거 | 건수 |
|---|---:|
| `시도` = 부산 | 18,668 |
| 부산일자리정보망 출처인데 지역 미상 | 1,579 |
| `지역원문` 에 "부산" 포함 (다지역 공고) | 375 |
| 부산 소속 시군구인데 시도가 빈 값 | — |

- **다지역 공고를 포함**합니다. `서울, 부산, 대전` 처럼 부산이 끼어 있으면 부산 근무가
  가능한 공고이므로 넣습니다.
- **부산일자리정보망의 지역 미상은 전부 부산**으로 봅니다. 부산광역시가 운영하는
  지역 포털이므로 지역이 안 적혀도 부산 공고입니다.

결과: 원본 30,584행 → 통합 **20,622건**.
