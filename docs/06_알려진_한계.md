## 1. 담당업무 — 사이트마다 확보율이 다르다

**"구체적으로 어떤 일을 하는지"** 가 이 데이터셋에서 가장 중요한 정보입니다.
그런데 원본이 이 필드를 가진 정도가 사이트마다 크게 다릅니다.

| 사이트 | 상세 | 담당업무 | 원인 |
|---|---:|---:|---|
| 리멤버·원티드·점핏·미디어잡 | 193 | **100%** | API 가 `main_tasks` 를 준다 |
| 사람인 | 5,670 | **91%** | 상세요강이 정형 템플릿 |
| 잡코리아 자체 | 3,979 | **65%** | 상세요강 iframe 을 따로 받아 해결 |
| 잡코리아 워크넷 연계 | 4,214 | **63%** | 고용24 에서 2,637건 확보. 나머지는 원본 마감 |
| 부산일자리정보망 | 25,326 | **16%** | 워크넷 등록분만 원본에 있다 |
| 커리어 | 5,070 | **0%** | 부산분 전량이 워크넷 연계 |

### 잡코리아 — 상세요강이 메인 페이지에 없다

```
/Recruit/GI_Read/{gno}                  '상세요강' 제목만, 내용은 비어 있음
/Recruit/GI_Read_Comt_Ifrm?Gno={gno}    담당업무 본문은 여기
```

메인만 파싱해서 0% 였습니다. iframe 을 한 번 더 받도록 고쳤습니다.
공고당 2요청이 되지만 이 필드가 그만한 값어치가 있습니다.
이미지로만 된 공고는 여전히 빈칸입니다(표본 5건 중 1건).

### 부산일자리정보망 — 원출처별로 갈린다

```
work24.go.kr (워크넷)   3,964 / 3,965   100%
saramin.co.kr              39 / 15,519    0.3%
jobkorea.co.kr              0 /  5,751    0%
```

사람인·잡코리아 재노출분은 이 사이트가 상세를 받아오지 않습니다.
잡코리아분 5,751건은 `GI_No` 교차 연결로 잡코리아 상세에서 메웁니다.

### 커리어 — 방법이 없다

부산분 표본 25건이 전부 워크넷 연계였고, 상세페이지에 담당업무·관련키워드·업종이
하나도 없습니다. 워크넷 ID 도 노출하지 않아 원본 추적이 안 됩니다.

### 워크넷 — 목록은 막혔지만 상세는 열려 있다

도메인이 둘인데 정책이 다릅니다.

| 도메인 | robots | 판정 |
|---|---|---|
| `work.go.kr` (구) | `User-Agent: *` 가 `/empInfo/` **전면 차단** | 목록 수집 불가 (부산 8,073건 확인만) |
| `work24.go.kr` (신) | `/wk/` **허용** (`/cm/common/`·`/sa/`·`/ei/` 만 차단) | 상세 수집 가능 |

신 도메인은 목록 페이지가 렌더링되지 않아 진입점이 없었는데,
**잡코리아 워크넷 공고가 work24 상세를 iframe 으로 직접 걸고 있어** 우회로가 열렸습니다.

```html
<iframe src="https://www.work24.go.kr/wk/a/b/1500/empDetailAuthView.do
             ?wantedAuthNo=K130112609080002&infoTypeGroup=tb_workinfoworknet">
```

여기서 담당업무와 **표준 직종 분류**가 나옵니다.

```
담당업무  CGV 부산 센텀시티점 미화원 구인 합니다. 주 업무 : 상영관청소, 분리수거 및 화장실 청소
직종      건물 청소원(공공건물,아파트,사무실,병원,상가,공장 등)
```

`src/work24_detail.py` 가 2단계로 받습니다 — 잡코리아 Ext 페이지에서 `wantedAuthNo` 추출 →
work24 상세 파싱. **4,214건 중 2,637건 확보**했고 품질이 매우 좋습니다.

```
직종 100%  직무키워드 100%  학력 100%  경력 100%
급여 100%  근무형태 100%   상세주소 100%  모집인원 100%  담당업무 99%
```

**나머지 1,577건은 실패가 아니라 마감분입니다.** 1.2KB 자동제출 폼이 200 으로 오는데
그 안에 이유가 적혀 있습니다.

```javascript
var msgStr = '마감된 채용정보입니다.';
```

워크넷 원본은 내려갔는데 잡코리아에는 아직 남아 있는 공고라 재시도해도 소용없습니다.
응답이 200 이고 HTML 도 정상이라 조용히 실패하므로, 파서가 이 문구로 걸러냅니다.

커리어 부산은 워크넷 ID 를 노출하지 않아 이 경로를 쓸 수 없습니다.

## 2. 채용인원 미정 — 잡코리아 50%

잡코리아 공고의 절반이 `○ 명` 입니다. 기업이 입력하지 않은 것이라 상세 어디에도
없습니다. **복구 불가.**

| 출처 | 명시 | 미정 |
|---|---:|---:|
| 부산일자리정보망 | 99% | 1% |
| 잡코리아 | 48% | 50% |
| 사람인 | 부분 | 자유 서술 공고엔 없음 |

미정을 0으로 잡으면 수요가 과소, 1로 잡으면 과대가 됩니다.
그래서 세 칸으로 나눠 두었으니 집계 방식은 분석 단계에서 정하면 됩니다.

```
모집인원원문   "1 명"  "○ 명"  "(3명)"    사이트 표기 그대로
채용인원        1      (빈칸)    3        숫자만
채용인원구분   명시     미정     명시       집계 시 선택 기준
```

## 3. 직무가 표준 분류가 아니다

사이트마다 자체 태그 체계라 그대로는 집계가 안 됩니다.

```
잡코리아  "국제금융, 금융, 은행, 문서관리, 전산입력, 서무, 행정, …"
사람인    "SNS마케팅, 광고마케팅, 바이럴마케팅, 콘텐츠마케팅"
커리어    "기구설계, 자동차부품개발, CATIA"
부산잡    "제도사"  ← 이것만 표준 직업분류(KECO)
```

**미착수.** 표준 체계로 재분류해야 직무별 수요 집계와 전공 연결이 가능합니다.
후보는 KECO(한국고용직업분류)와 잡코리아 21대분류입니다.

## 6. 사람인 상세 — IP 차단으로 중단

4워커 3req/s 로 6,400건을 받다가 **IP 레벨 차단**을 당했습니다.
HTTP 오류가 아니라 TCP connect 자체가 안 됩니다(`연결 0.000000s`).
경고 없이 방화벽 단에서 끊겼습니다.

```
확보    5,670건 (담당업무 91%)
미확보  8,276건
```

**목록 13,946건은 온전합니다.** 회사명·공고제목·직무태그·학력·경력·고용형태·
지역·마감일이 모두 있고 직무 태그는 100% 입니다. 막힌 건 상세의 서술형 필드뿐입니다.

### 부산일자리정보망 경유로 일부 보완

부산잡이 사람인 공고를 재노출하면서 상세를 함께 갖고 있고, 거기에 원출처
`rec_idx` 가 적혀 있습니다. `pipeline/detail_join.py` 가 이걸로 교차 연결합니다.

```
부산잡 상세가 가진 사람인 원출처   12,820건
미확보 8,276건 중 메운 것          3,761건
어느 쪽으로도 상세 없음            4,515건
```

단 사람인 원출처 공고에는 `직무내용` 이 없습니다. 얻는 것은
**고용형태·근무지역·경력학력조건·임금조건·모집인원·업종** 입니다.

### 교훈 — 실패가 조용했다

워커 4개가 전부 연결 대기에 물려 6분간 아무것도 못 하는데 프로세스는 살아 있고
로그도 마지막 줄에서 멈춰만 있어 진행 중처럼 보였습니다.
`common.fetch_many` 에 **연속 실패 60건이면 중단**하는 차단 감지를 넣었습니다.

## 그 밖에

### 중복 병합에서 일부러 남긴 것

회사·직무가 같아도 아래는 병합하지 않습니다. 중복이 아니라 실제로 다른 공고입니다.

| 예 | 차이 |
|---|---|
| 세움병원 간호 | 병동/외래, 간호사/수간호사/간호조무사, 야간전담 여부 |
| ㈜신건 배송 | 부산·울산·강원·경북 / 부산시 전지역 — 담당 권역 |
| 에스엠서치 상담 | KT / 롯데카드 / NH농협카드 — 고객사 |

`근무시간`·`근무형태`를 상세에서 확보하면서 이 판정이 더 정확해졌습니다.

### 스냅샷 시점 고정

`SNAPSHOT = "2026-09-07"` (`src/pipeline/normalize.py` 상단 상수).
이미 수집된 원본이 그 시점의 스냅샷이므로, 날짜만 바꾼다고 다른 시점 데이터가
나오지는 않습니다.
