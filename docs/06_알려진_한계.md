# 알려진 한계

데이터를 쓰기 전에 읽어야 하는 문서입니다.

---

## 1. 직무 칸이 채워져 있다고 수집이 된 것은 아니다 · **미해결**

부산 통합 20,622건 중 직무 채움률은 91% 입니다.
**그런데 이 91%의 상당수는 사이트에서 수집한 값이 아니라 공고제목에서 추론한 값입니다.**

### 무슨 일인가

부산 데이터의 78%(16,046건)가 **부산일자리정보망** 단독 출처입니다.
그런데 이 사이트의 원본 직무 칸에 들어 있는 값은 세 가지뿐입니다.

```
기업채용  25,246
해외채용     569
공공채용      80
```

이건 직무가 아니라 **메뉴 이름**입니다. 100% 채워져 있지만 정보량은 0 입니다.
현재 파이프라인은 이 값을 버리고 공고제목에서 직무를 추출해 채우고 있습니다.

즉 부산 데이터 대부분의 직무는 **크롤링 결과가 아니라 제목 파싱 결과**입니다.
그래서 상위 빈출 값에 `직원`(3,126) `사원`(1,939) 같은 일반 명사가 올라옵니다.
제목에 구체적 직무가 없으면 그 이상을 알아낼 수 없기 때문입니다.

### 원인

`src/busanjob.py` 가 **목록 페이지만 수집하고 상세페이지를 받지 않습니다.**

상세페이지에는 실제로 아래 필드가 있습니다.

```
/view.do?no=1308&pgMode=show&id={id}
  → div.board-view__dcont 안의 라벨/값 쌍
```

| 필드 | 내용 | 현재 |
|---|---|---|
| **직무내용** | 실제 담당 업무 서술 | 미수집 |
| **직종** | 표준 직업분류명 (예: "제도사", "강구조물 가공원") | 미수집 |
| **업종** | 산업 분류 (예: "의료(병원종류별)") | 미수집 |
| **고용형태** | 정규직/계약직/기간제 | 미수집 → 채움률 21%의 원인 |
| **근무지역** | 다지역 상세 (목록보다 정확) | 부분 |
| 경력/학력조건, 임금조건, 모집인원 | | 미수집 |

또 상세페이지 스크립트에 **원출처 URL 이 그대로 들어 있습니다.**

```js
wantedInfoUrl = 'https://www.jobkorea.co.kr/Recruit/GI_Read/49933356?...'
wantedInfoUrl = 'https://www.work24.go.kr/...?wantedAuthNo=KF10912609070022'
wantedInfoUrl = 'http://www.saramin.co.kr/zf_user/jobs/relay/view?rec_idx=54753349'
```

### 출처별로 얻을 수 있는 것

부산 통합 20,622건을 부산일자리정보망 원출처로 나누면 이렇습니다.

| 원출처 | 건수 | 상세페이지에 `직무내용` | 대책 |
|---|---:|---|---|
| 워크넷(고용24) | 3,499 | **있음** | 상세 수집하면 즉시 해결 |
| 알리오 | 52 | **있음** | 〃 |
| 수동등록(구청) | 20 | **있음** | 〃 |
| 부산 자체등록 | 15 | **있음** + `직종` | 〃 |
| 잡코리아 | 3,494 | 없음 | 상세의 `GI_Read/{GI_No}` 로 자체 잡코리아 데이터와 조인 |
| 사람인 | 12,214 | 없음 | 상세의 `rec_idx` → 사람인 원문. **정책 확인 필요(아래)** |
| 해외(월드잡) | 561 | — | 목록에 직무가 이미 있음 |

### 사람인 수집에 대한 정책 판단 — 보류

12,214건이 사람인 원출처입니다. 확인 결과는 이렇습니다.

- `robots.txt` : `/zf_user/jobs/relay/recruit-view` 를 **명시적으로 Allow**.
  `/zf_user/jobs/relay/view` 는 Disallow 목록에 없음
- 공고 페이지 본문·푸터 : 크롤링 금지 고지 **없음**
- 이용약관 : "개인회원은 서비스를 이용하여 얻은 정보를 회사의 사전동의 없이
  복사, 복제, 번역, 출판, 방송 기타의 방법으로 사용하거나 이를 타인에게 제공할 수 없습니다"
  → **회원 의무 조항**. 비회원·비로그인 수집에 그대로 적용되지는 않으나
  재배포에 제약이 될 수 있음

부산일자리정보망이 노출하는 사람인 공고는 사람인 **공식 job-search API** 로 받아간 것입니다
(URL 에 `utm_source=job-search-api`). 즉 재배포 자체는 사람인이 허용한 경로입니다.

→ **팀 결정 필요.** 12,214건의 직무 품질이 여기 달려 있습니다.

### 작업 순서 (미착수)

1. `src/busanjob.py` 에 상세 수집 패스 추가 — 약 25,000 페이지
   → `직무내용` `직종` `업종` `고용형태` `근무지역` + 원출처 URL 확보
2. 잡코리아 원출처 3,494건을 `GI_No` 로 자체 데이터와 조인
3. (정책 결정 후) 사람인 원출처 12,214건 처리
4. `normalize.py` 가 `직무내용` 을 직무 추출의 1순위로 쓰도록 수정

예: "2026년 상반기 신입사원 공개채용", "○○기업 인재 모집".

## 4. 잡플래닛 데이터 처리

잡플래닛은 "모든 컨텐츠의 무단 전재, **무단 수집**, 재배포 및 **AI 학습 이용 금지**" 를
게시하고 있습니다. 데이터셋 구축 목적과 정면으로 충돌합니다.

수집분 50,118건 중 잡코리아에서 같은 공고를 확보한 49,048건(97.9%)을
`제외됨/잡플래닛_잡코리아중복.csv` 로 분리했습니다. 남은 **1,070건**이 아직 데이터에 있습니다.

`src/pipeline/reconcile_jobplanet.py` 가 이 대조를 수행합니다.

→ **팀 결정 필요.** 남은 1,070건을 버릴지 여부.

## 5. 중복 병합에서 일부러 남긴 것

회사·직무가 같아도 아래는 병합하지 않았습니다. **중복이 아니라 실제로 다른 공고**입니다.

| 예 | 차이 |
|---|---|
| 세움병원 간호 | 병동/외래, 간호사/수간호사/간호조무사, 야간전담 여부 |
| ㈜신건 배송 | 부산·울산·강원·경북 / 부산시 전지역 — 담당 권역 |
| 에스엠서치 상담 | KT / 롯데카드 / NH농협카드 — 고객사 |

회사명 + 공고제목이 **완전히 같은** 잔존 중복은 0건입니다.

## 6. 스냅샷 시점 고정

`SNAPSHOT = "2026-09-07"`. 이 날짜 기준으로 마감되지 않은 공고만 담았습니다.
`src/pipeline/normalize.py` 상단에 상수로 있습니다.
다른 시점 데이터를 만들려면 이 값을 바꾸고 파이프라인을 다시 돌립니다.
단 **이미 수집된 원본이 그 시점의 스냅샷**이므로, 미래 날짜로 바꾼다고
그때 열려 있던 공고가 나오지는 않습니다.
