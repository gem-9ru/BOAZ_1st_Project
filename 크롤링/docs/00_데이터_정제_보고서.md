# 2. 정제 파이프라인

## 2.1 필드 정규화 (240,773 → 227,214)

사이트마다 컬럼 이름·값 표기가 전부 다르다. 하나의 스키마로 접었다.

```
사람인   "경력 3년↑"    잡코리아 "경력 3년 이상"   부산일자리정보망 "3년이상"
                    ↓
        경력구분=경력 · 최소연차=3
```

**제외한 13,559행**은 셋이다.

| 제외 | 건수 | 왜 |
|---|---:|---|
| 마감된 공고 | 9,158 | 기준일(2026-09-07) 이전에 마감. "지금 모집 중인 수요"를 보는 데이터다 |
| 알바 공고 | 4,231 | 제목·고용형태로 판정. 청년 정규 일자리 수요와 성격이 다르다 |
| 게시 고지로 제외 | 170 | 잡부산시대 — 상세페이지에 재배포 금지 고지 (4.4절) |

`공고제목`·`공고URL`이 없는 행은 각 수집기에서 이미 버려지므로 여기 오지 않는다.

## 2.2 사이트 간 중복 병합 (227,214 → 161,351)

같은 채용건이 여러 사이트에 동시에 올라간다. 그대로 세면 수요가 부풀려진다.
**신뢰도 높은 순서로 3단계**를 적용하고, 앞 단계에서 묶인 건은 뒤 단계에서 건드리지 않는다.

| 단계 | 기준 | 왜 |
|---|---|---|
| 1 확정 | 사이트가 스스로 밝힌 외부 원본ID | 잡플래닛이 `jobkorea_posting_id`를 노출한다. 추측이 0% |
| 2 완전일치 | 회사키 + 제목키 + 시도가 모두 같음 | |
| 3 유사도 | 회사키 동일 + 제목 토큰 Jaccard ≥ 0.95 | 0.60~0.95 구간은 자동 병합하지 않고 검수 후보로 뺀다 |

**제목 비교 시 괄호 안은 지우지 않는다.** 괄호에 직무·지역 같은 식별 정보가 들어 있다.

```
"건설안전부 (안전관리자)"  vs  "건설안전부 (보건관리자)"      ← 서로 다른 공고
"울산 건축공사관리"        vs  "군산 건축공사관리"            ← 서로 다른 공고
```

괄호는 기호만 벗기고 내용은 살렸다. `채용공고`·`급구`·`D-3` 같은 순수 장식 문구만 제거한다.

병합할 때 **필드는 한 행에서 통째로 가져온다.** 급여형태·최소·최대를 서로 다른
사이트 행에서 골라 오면 `시급 / 2,600만원 / (빈칸)` 같은 조합이 나온다.

## 2.3 부산 근무 판정 (161,351 → 25,135)

지역 칸이 본사 주소인 공고가 많아 지역 필드만 믿을 수 없다.
**상세 페이지의 근무지주소를 정본으로 본다.**

| 판정근거 | 건수 | 확실도 |
|---|---:|---|
| 시도 = 부산 | 15,840 | 강 |
| 근무지주소 = 부산 | 7,718 | 강 |
| 다지역 공고(부산 포함) | 795 | 중 |
| 부산일자리정보망 · 지역 미상 | 619 | 중 |
| 지역원문에 부산 포함 | 125 | 강 |
| 제목에 부산 지명 | 38 | 약 |

- **다지역 공고**(`서울, 경기, 부산, 경남`)는 포함하되 확실도 `중`으로 표시했다. 부산 채용이 맞지만 실제 근무지 확정은 안 된다.
- **부산일자리정보망 지역 미상 619건**은 부산으로 봤다. 부산광역시가 운영하는 지역 포털이고 게시 목적 자체가 부산 구인·구직 연결이다.
- 근무지주소가 있는데 부산이 아니고 지역 칸에도 부산이 없으면, 제목에 「부산」이 있어도 제외했다(**판정보류 190건**).
- 제목 지명 사전에서 `기장`·`사상`·`남구`·`동구`·`중구`·`서구`·`북구`는 뺐다. 「세무기장」·「사상 최대」처럼 다른 뜻으로 더 자주 쓰이고, 나머지는 다른 광역시에 같은 이름이 있다.

## 4.3 원본 보존 원칙

정제 과정에서 값을 바꿀 때 **원문을 함께 남긴다.** 중간 산출물
`부산/부산_공고_직종분류.csv`(70컬럼)에 `원본_경력`·`원본_급여` 등이 그대로 있어

우대사항·URL 목록·`원본_` 컬럼은 중간 산출물에 남아 있으므로 필요하면 조인하면 된다.

# 5. 직종코드 분류

한국고용직업분류(KECO) 6자리 코드 1,130개와, 팀이 정한 **13대분류**를 붙였다.
전 과정이 **결정적(deterministic)** 이다 — LLM·임베딩을 쓰지 않았다. 같은 공고가
실행마다 다른 코드를 받으면 사이트 간 비교가 깨진다.

## 5.1 근거별 부여 경로

신뢰도 높은 순서로 적용하고, 앞 경로에서 붙은 건은 뒤에서 건드리지 않는다.

| 근거 | 건수 | 확실도 | 무엇 |
|---|---:|---|---|
| 고용24 직접 | 2,559 | 강 | 고용노동부가 붙인 공식 직종코드 |
| 별칭 일치 | 4,094 | 강 | 공식 명칭 1,325개 + 별칭 518개와 문자열 일치 |
| 학습사전 | 655 | 중 | 정답 2,559건에서 «직무 토큰 → 직종코드»를 학습 (순도·건수 임계 통과분) |
| 상위합의 | 15,161 | 약 | 후보 여럿의 상위 분류가 한 곳으로 모일 때 **대분류만** 부여 |
| 추천 1순위 | 804 | 약 | 제목·담당업무 기반 추천의 1순위 |

## 5.2 세세분류는 못 믿을 곳에서 멈춘다

홀드아웃 실측으로 계층별 정확도를 재보고, **믿을 수 있는 깊이까지만** 부여했다.

| 계층 | 정확도 |
|---|---:|
| 중분류 | 97.4% |
| 소분류 | 96.1% |
| 세분류 | 95.2% |
| 세세분류(6자리) | 77.5% |

그래서 상위합의 경로는 6자리를 주지 않고 **대분류 1자리만** 낸다.
6자리가 필요한 15,185건은 `직종추정코드` 컬럼에 참고값으로 따로 담았다 — **집계에 쓰면 안 된다.**

## 5.3 실측 정확도

정답 세트 2,559건을 5-fold 교차검증했다(학습에 쓴 토큰은 각 fold에서 제거).

| | |
|---|---:|
| **팀 13대분류** | **88.8%** |
| KECO 대분류 | 88.2% |
| 총변동거리(TVD) — 정답 분포 vs 예측 분포 | **2.4%p** |

**TVD 2.4%p가 이 프로젝트에서 가장 중요한 수치다.** 분석 주제가 학과 배출과
기업 수요의 *비율 비교*이므로, 분류 오류가 특정 직군으로 쏠리면 결론이 뒤집힌다.
2.4%p는 분포가 거의 안 흔들린다는 뜻이라 비율을 그대로 쓸 수 있다.

## 5.4 미분류 1,206건의 사유

| 사유 | 건수 | |
|---|---:|---|
| 직무없음 | 606 | 원문에 직무 정보가 없다 |
| 무정보토큰 | 295 | 직무 칸이 `직원`·`사원`·`현장` 뿐 |
| 확정불가·추정만 | 289 | **13대분류는 붙어 있고 6자리만 없다** |
| 분류표없음 | 9 | 다직종 통합공고·연수 프로그램 모집 |
| 사전제외 | 7 | 직위어만 있고 담당업무도 없다 |

`직종신뢰도 = 미분류` 기준 1,206건이다. 이 중 289건(`확정불가·추정만`)과
업종으로 대분류를 보강한 165건은 **13대분류가 붙어 있어** 7.1 분포표에서는
자기 분류로 집계된다. 그래서 7.1의 미분류는 752건이다.

**901건(직무없음 + 무정보토큰)은 사람이 봐도 정할 수 없다.**
`2026년 하반기 신입사원 공개채용` 같은 제목이 전부이고 담당업무 칸이 비어 있다.

## 7.3 유의사항

1. **집계 축은 `직종분류코드`(13대분류).** 6자리 `직종코드`는 34.5%만 채워져 있다.
2. **`직종추정코드`는 집계에 쓰지 않는다.** 세세분류 실측 정확도가 낮은 참고값이다.
3. **연봉은 41%만 명시.** 면접후결정 8,609건이 최대 덩어리다. 연봉 분석은 명시된 것만 대상으로 하고 그 사실을 밝혀야 한다.
4. **`시군구` 미상 7.7%.** 다지역 공고와 지역 표기 없는 공고다. 지역 차트는 미상을 제외하거나 별도 표기.
5. **게재사이트수는 수요 강도의 대리지표.** 여러 사이트에 올린 공고일수록 채용 의지가 강하다고 볼 수 있지만, 대기업이 채널을 많이 쓰는 경향과 섞여 있다.
